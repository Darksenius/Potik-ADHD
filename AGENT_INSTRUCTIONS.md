# Інструкції для роботи над Потоком

Для продовження з другом або іншим ШІ: [передача роботи](docs/CONTINUING-WORK.md). [Карта екранів, сповіщень і продуктового задуму](docs/APP-MAP.md). Стандартний вхід для агентів — [AGENTS.md](AGENTS.md).

Актуальний стек — Kotlin/Compose, ViewModel/StateFlow та Room, Java-компоненти Android для сповіщень і файлів. [Повний нативний перехід](docs/roadmap/NATIVE-MIGRATION.md) N1–N5 завершено й опубліковано у v1.7.6.r26. Для нової роботи починайте від актуального main; контрольні SHA та перевірки — у передачі роботи. Стару вебреалізацію збережено в archive/web-reference як довідку; вона не є активним застосунком. [README](README.md) описує складання, [WORKFLOW](docs/WORKFLOW.md) — випуск.

Поточний випуск — [v1.7.6.r42](https://github.com/Darksenius/Potik-ADHD/releases/tag/v1.7.6.r42), код `89d1ff6`: вкладки пам’ятають пошук/фільтр/прокрутку та дату Плану; повернення з редактора задачі зберігає контекст. «Ще» пам’ятає прокрутку, переходи прибирають фокус/клавіатуру, пошук не викликає її при поверненні. На малому вікні шапка звільняє місце для введення зі збереженою нижньою навігацією. Відкрита нотатка не підміняє незбережене редагування при поверненні вкладки. 419 JVM і 81 API28 успішні; перший CI мав один нестабільний SnapshotStateObserver збій, локальний цільовий та повний CI-повтор на незмінному SHA пройшли без skip/зміни коду. Підписаний APK поверх r41 зберіг десять полів даних і theme/preferences; оглянуто 320×480dp/font130% з реальною клавіатурою та повернення майбутньої дати. APK/source публічно завантажуються з HTTP200 і перевіреними SHA-256/SOURCE_REVISION. Фізичний телефон не перевірений. Панель r41 (зона/колір/1–9/9+, без числа при нулі), менше коло та групування меню збережені. Room1/JSON2/один Repository та правила задач/переносу не змінені. Деталі, нестабільний CI-стек та попередні випуски — у передачі роботи.

## Межі

- Спочатку git status і поточна гілка. Зберігати чужі зміни; працювати невеликими оборотними комітами. Не переписувати застосунок з нуля.
- Власник дозволив фінальний push і реліз після повної готовності та перевірок. Незавершений нативний перехід не релізити, проміжні теги не створювати. Конфігурацію підписування не змінювати.
- Дані фізичного телефона не очищати. Android instrumentation — в окремій nativeDebug (.native) на призначеному емуляторі. Несумісні дані архівувати до заміни; при відмові архіву оригінали зберігати.
- Any change of the Room version requires a Migration and a test. fallbackToDestructiveMigration is forbidden.
- Room v1, JSON formatVersion2. Не перейменовувати persisted fields без узгодженої міграції. UI і сповіщення надсилають команди одному Repository; другий writer заборонений.
- Не повертати Pomodoro, дитячу звичку, окремий шар води чи Вхідні. Погоджені правила зон/переносу й незалежних виконань пресетів зберігати. З r29 у застосунку за замовчуванням усі задачі, п’ять найближчих на початку; у сповіщенні — одна панель до п’яти доречних задач із гортанням. Запланована «Не зараз» відкладається на одну годину (інший час — у застосунку), звичайна — за чинними правилами зон. Маркер ///12:40/// будь-де в назві створює заплановану задачу з нагадуванням; текст нотаток не розбирається.
- src/content/task-types.json — єдиний каталог десяти типів. Інші авторські каталоги також у src/content; Gradle пакує їх локально. Згенеровані assets та outputs не редагувати.
- Ключі підпису, локальні налаштування, дані користувача не комітити.

- Візуальні орієнтири власника: від Things лише легкість і якість деталей UI, без його логіки чи архітектури; Todoist виключено. Structured — лише загальна візуальна мова, без конкретних іконок і продуктових правил. Проста задача — мінімальне захоплення тексту й повернення уваги у вибраний час; решта типів — у повному режимі «Складена».

## Перевірка

JDK21, Android SDK36, min24/target36. Node/npm не потрібні для APK. У android/:

```bash
./gradlew :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest
./gradlew -PflowTestBuildType=nativeDebug :app:connectedNativeDebugAndroidTest
```

На Windows — gradlew.bat. Під час роботи — цільові перевірки, повний набір перед кандидатом або зміною спільного механізму. Android9/API28 обов’язковий для запуску, сповіщень, відновлення й офлайн-сценарію. Компіляція не доводить виконання instrumentation. Записувати фактичний результат і неперевірене. Не повторювати успішне без нової причини.

## Версія та випуск

package.json — єдине джерело версії, синхронно змінювати lockfile. 1.7.6-r26 → 1.7.6.r26, тег v1.7.6.r26, code1070626. Формула: major*1000000 + minor*10000 + patch*100 + revision; minor/patch/revision 0..99.

Перед створенням тега UI-змін оглянути реальні екрани на API28/320dp/font130% з відкритою клавіатурою; перевірка лише після приховування клавіатури не доводить доступність кнопок.

Перед випуском: особистий запис від першої особи в src/content/release-notes.json (зміни, короткі дії й очікування, перевірене та незавершене), Fastlane changelog. Попередні записи зберігати. Gradle перевіряє версію запису, node scripts/check-release-notes.mjs перевіряє повну структуру.

Ревізія: валідний SOURCE_REVISION із середовища, Git або маркер релізного архіву. Без відомого SHA — unknown. node scripts/package-source.mjs із чистого checkout пакує всі tracked джерела та маркер SHA.

Release workflow викликає нативну валідацію того самого SHA; лише успіх JVM/компіляції та API28 дозволяє підписання й чернетку релізу. Секрети доступні лише build job. Перед публікацією перевірити підписаний APK на API28, версію, підпис, фактичний asset і публічне завантаження. Не перевикористовувати опубліковані теги.
