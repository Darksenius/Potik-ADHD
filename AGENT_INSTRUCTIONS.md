# AGENT_INSTRUCTIONS.md — читай це першим

Ти отримав повний знімок репозиторію **Potik-ADHD** (застосунок «Потік»
для людей з РДУГ) з уже виконаним рефакторингом веб-частини: монолітний
`www/index.html` (4503 рядки) переписаний на **React + TypeScript + Vite
+ Zustand**. Ти не продовжуєш рефакторинг — твоя задача: **зібрати,
перевірити і опублікувати** те, що вже зроблено.

## 0. Що це за архів

Це ПОВНИЙ репозиторій (з `.git`, історією і remote на GitHub), у якому:
- `android/`, `fastlane/`, `docs/F-DROID.md`, `LICENSE`, `cdp-*.js` —
  повністю НЕЗМІНЕНІ, ідентичні поточному GitHub.
- `src/`, `index.html` (корінь), `vite.config.ts`, `tsconfig.json`,
  `package.json`, `.gitignore`, `scripts/embed-oss.js`,
  `.github/workflows/release.yml` — НОВІ/ЗМІНЕНІ (сам рефакторинг).
- `www/` — ПОРОЖНЯ. Це тепер build-артефакт (`npm run build` заповнить
  її заново), не комітиться.
- `docs/REFACTOR-PLAN.md` — детальна мапа: що зроблено, як саме, і
  чекліст верифікації паритету зі старою версією. **Прочитай його
  повністю перед тим, як щось міняти в коді.**

## 1. Що вже перевірено (і як), щоб ти не витрачав час повторно

Кожен файл `src/` пройшов, у копії цього самого репозиторію:
- `npm install && npm run build` (tsc типчекінг + vite build) — без помилок
- `node scripts/embed-oss.js` — вшиває код/ліцензію в зібраний `www/index.html`
- `npx cap sync android` — успішно копіює веб-assets в Android-проєкт

**НЕ перевірено** (немає браузера/Android SDK в середовищі, де це писалось):
живий рендер у браузері, реальна Android-збірка через Gradle, УІ на
екрані телефону. Це твоя основна робота нижче.

## 2. Послідовність дій

### Крок А — Встанови залежності й зібери веб-частину
```bash
npm ci
npm run build              # vite build → www/
node scripts/embed-oss.js  # вшиває LICENSE + повний код src/ у www/index.html
```
Якщо `npm run build` падає з помилкою TypeScript — це РЕГРЕСІЯ, якої не
було в момент здачі; розберись і виправ, не обходь `--force`/`any` без
потреби.

### Крок Б — Локальна перевірка в браузері (ОБОВ'ЯЗКОВО перед Android)
```bash
npm run dev
```
Відкрий у браузері. Це не ідентично Android-збірці (нема нативного
мосту `window.FlowBridge`/`Capacitor.Plugins.FlowNotif` — застосунок сам
це толерує, working без них), але 90% UI/UX і бізнес-логіки видно вже
тут. Пройдись `docs/REFACTOR-PLAN.md` розділ 4 («Чекліст верифікації
паритету») — це буквальний список того, що звірити.

### Крок В — Android
```bash
npx cap sync android
cd android
./gradlew assembleDebug     # або через Android Studio: Open → android/ → Run
```
Постав APK на пристрій/емулятор і перевір:
- З'являється foreground-сповіщення з поточною зоною/задачами, оновлюється щохвилини
- Кнопки на сповіщенні (виконати/відкласти/++) працюють — це `handleNativeEvent()` у `src/bridge/nativeBridge.ts`
- Будильники/заплановані задачі спрацьовують у фоні, коли застосунок згорнутий
- Довідка → «Ліцензія та вихідний код» показує актуальний `src/`-код (не старий монолітний файл)

### Крок Г — Якщо все ОК: git-гілка і пуш
Створи ОДНУ гілку під усю цю міграцію (не гілку на кожен білд):
```bash
git checkout -b refactor/vite-react-migration
git add -A
git commit -m "Рефакторинг веб-частини: Vite+React+TS+Zustand замість монолітного www/index.html

Повний перенос усієї бізнес-логіки й UI (13 типів задач, зони, планувальник,
гейміфікація, нотатки, нативний міст, Android-сповіщення, Web Notification API,
Export/Import). Деталі й мапа перенесення — docs/REFACTOR-PLAN.md.
android/ не змінювався, контракт FlowBridge/FlowNotif той самий."
git push -u origin refactor/vite-react-migration
```
Для нумерації тестових білдів (НЕ гілок) онови `"version"` у
`package.json` за схемою `1.7.5b.1`, `1.7.5b.2`, ... — збільшуючи
останнє число з кожним новим білдом у ЦІЙ ЖЕ гілці.

## 3. Тверді правила — НЕ порушувати

1. **Не перейменовуй ключі в `src/types/index.ts` (`AppState`) і не міняй
   `services/persistence.ts`** без крайньої потреби — це те, що зберігає
   побітову сумісність localStorage/Room з існуючими користувачами. Зміна
   імені поля = втрата їхніх даних при першому запуску нової версії.
2. **Не міняй сигнатури в `src/bridge/nativeBridge.ts`**
   (`window.FlowBridge.*`, `window.Capacitor.Plugins.FlowNotif.*`) — вони
   мають відповідати реальному Java-коду в `android/app/src/main/java/
   com/flow/adhd/FlowBridge.java` і `FlowPlugin.java`. Якщо треба щось
   змінити в контракті — міняй ОБИДВІ сторони синхронно.
3. **Не редагуй `www/`** вручну — вона перегенеровується збіркою.
4. **Не запускай `node scripts/embed-oss.js` до `npm run build`** —
   впаде з чіткою помилкою (він читає вже зібраний `www/index.html`).
5. Якщо знайдеш візуальну різницю з оригіналом (кольори/відступи/шрифти)
   — дивись `src/styles/global.css` (весь CSS перенесено туди механічно,
   `sed`, з оригінального `www/index.html` через git-історію, якщо
   знадобиться звірити рядок-в-рядок).

## 4. Якщо щось зламано

`docs/REFACTOR-PLAN.md` має повну мапу «рядок оригіналу → новий модуль»
для кожної секції логіки — знайдеш, звідки саме перенесено конкретну
поведінку, і звіриш з git-історією файлу `www/index.html` (він був у
репозиторії до цього рефакторингу, тому `git log -p -- www/index.html`
покаже оригінальний код).

Два свідомі винятки, які НЕ є багом, якщо поведінка відрізняється:
- Debug-режим підміни системного часу (`S.liveMode`/`debugTime` в
  оригіналі) — навмисно не перенесено, інструмент розробника.
- Сторінка `widget` — в оригіналі теж недосяжна (`goToWidget()` ніде не
  викликався, сама сторінка мала `display:none!important`).
