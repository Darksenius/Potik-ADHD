# Наскрізні перевірки Потоку: Maestro та альтернативи

Дата дослідження: 21.10.2026. Це рішення щодо інструменту, а не звіт про запуск Maestro: його ще не встановлено й жоден Flow на Потоку ним не виконано.

## Рекомендація

Спробувати Maestro CLI як невеликий зовнішній шар перевірки користувацьких сценаріїв. Залишити чинні Kotlin/JVM, Compose та Android instrumentation для точного контролю правил, Room, нагадувань, досвіду й повторних дій. Не переносити в Maestro всі перевірки й не робити його умовою релізу до підтвердження роботи на API28.

Maestro виконує описані в YAML натискання, введення, прокрутку й очікування на встановленому APK через ADB; може діяти поза застосунком, зокрема в системній шторці. Вбудовувати його в APK Потоку не потрібно. Це підходить для перевірки того, що людина справді може пройти весь шлях, а не лише викликати правильну команду. [Офіційний опис Android](https://docs.maestro.dev/get-started/supported-platform/android), [CLI](https://docs.maestro.dev/maestro-cli).

Важливий приклад із r29: прямі перевірки кнопок RemoteViews не довели, що згорнута панель не обрізана системною висотою. Огляд реальної шторки виявив обрізаний другий рядок; висоту виправлено. Зовнішній сценарій зі знімком екрана допоможе регулярно перевіряти такі місця. Автоматичне «елемент існує» саме по собі теж не доводить якісного вигляду.

## Android 9 і українське введення: що відомо

Перевірено актуальний реліз Maestro `cli-2.11.0` від 29.09.2026. На частині сторінок є розбіжності з його кодом:

- QuickStart перелічує API29 та новіші, а Android-модуль цього тегу має `minSdk = 24`. Отже, немає заявленої в цьому модулі мінімальної межі, що виключала б API28. Це підстава для пілоту, а не доказ проходження нашого сценарію на Android9. [QuickStart](https://docs.maestro.dev/get-started/quickstart), [код версії 2.11.0](https://github.com/mobile-dev-inc/Maestro/blob/cli-2.11.0/maestro-android/build.gradle.kts).
- Сторінка Android Native ще називає Unicode-введення обмеженням, проте драйвер цього тегу має окремий шлях `inputUnicodeText` через клавіатуру Maestro з поверненням попередньої клавіатури. Український текст і відновлення звичайної клавіатури треба перевірити фактично, включно з RemoteInput у шторці. [Документація](https://docs.maestro.dev/get-started/supported-platform/android/android-native), [драйвер 2.11.0](https://github.com/mobile-dev-inc/Maestro/blob/cli-2.11.0/maestro-client/src/main/java/maestro/drivers/AndroidDriver.kt).
- Чинні Compose `testTag` використовуються нашими внутрішніми тестами. Їхня доступність зовнішньому інструменту як resource ID у Потоку поки не підтверджена; глобального `testTagsAsResourceId` зараз немає. Для пілоту перевірити дерево доступності й використовувати тексти/описи, а за потреби окремою малою зміною експортувати стабільні ID. Не прив’язувати перевірки до координат конкретного екрана. [Офіційний опис роботи Maestro з Compose](https://docs.maestro.dev/get-started/supported-platform/android/jetpack).

На цьому ПК є Android SDK, JDK21 і окремий Potik_API28. Документація вже має нативне встановлення CLI у Windows; WSL не потрібен як початковий шлях. Починати локально, без Maestro Cloud і нової платної інфраструктури. [Встановлення CLI](https://docs.maestro.dev/maestro-cli/how-to-install-maestro-cli).

## Мінімальний пілот

Три перші сценарії, які мають довести користь інструменту:

1. **Задача з українською назвою й нотаткою:** короткий екран → клавіатура → збереження → повторне відкриття → точний текст. Знімок має показати доступну кнопку збереження.
2. **Реальна шторка:** швидко створити задачу й нотатку через RemoteInput без відкриття Activity; розгорнути панель, перейти між справами, виконати вибрану; переконатися, що інших справ не зачеплено й окремі картки не з’явились.
3. **Запланована справа:** назва з `///HH:mm///` на найближчий час → згортання → фактичне нагадування → «На 1 годину» → одна перенесена справа з правильним часом. Не підміняти чекання нагадування прямим викликом receiver.

Критерій успіху: повторюваний результат на API28, точний український текст, вибір елементів без координат, зрозумілий звіт і знімки при помилці. Пілот має зменшувати ручну роботу, а не вимагати довгого лагодження тестового інструменту.

Потім достатньо додати автозбереження блокнота після закриття, планування через пресет і відновлення з тестової SAF-папки. Точне нарахування досвіду, дедуплікацію команд, календарні межі/DST та архіви залишити швидким внутрішнім перевіркам.

Виконувати лише на призначеному емуляторі й окремій `.native` інсталяції, з явним вибором serial. Перед `clearState`, перевстановленням або відновленням перевіряти обидві ознаки. `clearState` стирає дані застосунку; шаблони з документації не запускати проти інсталяції власника.

## Порівняння для нашого проєкту

| Варіант | Що дає Потоку | Ціна супроводу / межа | Рішення |
| --- | --- | --- | --- |
| Чинні JVM + Compose/instrumentation | Правила зон і часу, стан Room, досвід, Undo, семантика екранів | Самі по собі не доводять увесь шлях через реальну системну шторку | Зберегти як основу |
| Maestro CLI | Короткі читабельні сценарії по готовому APK, прокрутка, клавіатура, системний UI | Спершу підтвердити API28, Unicode і RemoteInput; потрібен зовнішній інструмент | Кандидат для малого пілоту |
| Прямий Android UI Automator | Керування застосунком і системними екранами в нашому Kotlin/Android середовищі | Більше Kotlin-коду; тестова залежність, якої наразі явно немає в `app/build.gradle` | Найближча альтернатива, якщо Maestro не окупиться |
| Appium + UiAutomator2 | Зовнішнє керування Android через WebDriver, зокрема API28 | Додаткові сервер, драйвери й клієнтський код для одного Android-застосунку | Зараз зайва інфраструктура |

UI Automator офіційно призначений для взаємодії з користувацькими й системними застосунками та може тестувати release-збірки. Нова DSL 2.4 ще перебуває в розвитку; версію залежності обирати окремо, не оновлювати навмання під час релізу. [Android Developers](https://developer.android.com/training/testing/other-components/ui-automator).

Appium UiAutomator2 від версії 6 підтримує API26+, тобто API28 входить у заявлену межу; драйвер від версії 5 потребує Appium3. Технічна придатність є, але для Потоку це поки більше складових, ніж потрібно. [Офіційні вимоги драйвера](https://github.com/appium/appium-uiautomator2-driver#requirements).

## Межа рішення

Maestro — перспективний додаток до наших перевірок, а не вже інтегрована система й не виправлення UX саме по собі. Якщо пілот не проходить API28, не переносимо головну перевірку на новіший Android, щоб отримати зелений результат: використовуємо UI Automator на потрібній версії ОС.
