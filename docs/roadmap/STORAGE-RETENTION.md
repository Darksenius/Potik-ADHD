# Зберігання історії та журналів

`taskHistory` містить незмінні події завершення й скасування конкретного входження. Планувальник використовує його для минулих виконань, а денний журнал — для рядків завершених задач із початковими назвами. Нові події зберігають факти входження, але не копіюють чекліст: його поточний стан належить задачі, а історичні екрани не читають чеклісти зі знімка події. Раніше імпортоване поле `items` лишається прийнятним і зберігається.

`focusLog` зберігає окремі сесії фокусу з часом і тривалістю; його читають історія фокусу та часові рядки денного журналу. `planDayLog` зберігає щоденний підсумок: фокус, енергію, виконання рутин, пріоритети, кількість завершених задач і нотатку. Цей агрегат не містить ідентичності кожної задачі чи часу кожного завершення. Повна послідовність фактів завершення лишається у `taskHistory`.

Щоб повторити оцінку розміру без доступу до користувацьких даних, запустіть `node scripts/measure-state-size.mjs`. Фікстура синтетична: 365 днів, чотири події задачі на день, один знімок чекліста з п'яти пунктів на день, дві сесії фокусу та один підсумок планувальника на день. Скрипт порівнює UTF-8 розмір JSON для кожного поля та всього вибраного стану до і після вилучення `items` із подій. Це відтворюваний орієнтир, а не вимірювання реального профілю.

Наразі повна історія залишається без строку зберігання та компактування. Будь-яке майбутнє обмеження має зберегти явну відмінність між подіями `taskHistory` і агрегатами `planDayLog`; числа денного підсумку не відновлять втрачені входження.
