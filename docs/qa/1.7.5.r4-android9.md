# Android 9 startup regression — 1.7.5.r4

Date: 2026-10-07. Scope: the reported black screen in 1.7.5.r3 while the foreground notification works. All native data used here is synthetic; no user device was modified.

## Reproduction and cause

Baseline: tag `v1.7.5.r3`, commit `a273f635f69fbcb194e10f9e68db842056b3e16b`.
Isolated AOSP x86_64 Android 9/API 28 emulator, WebView 66.0.3359.158.

The baseline native debug launch logged `Uncaught TypeError: l.call(...).catch is not a function` from `index-BU20dmOT.js`, before React mounted. The root had zero children, while the native notification started.

Capacitor's embedded `native-bridge.js` returns a synchronous `{ remove }` from `Capacitor.addListener`; `JSExport.java` exposes that same return value as `Plugins.FlowNotif.addListener`. Calling `.catch` directly on that handle aborts bootstrap. The previous browser fixture used an async listener and did not reproduce this contract.

The fix normalizes both returns through `Promise.resolve` and catches synchronous registration failures. Native Java APIs, persistence schemas, `flow_v2`, and task IDs are unchanged.

Local evidence is retained under the task workspace's `outputs/android-startup/`: `api28-r3-debug-launch.log`, `api28-r3-seeded-state.json`, `api28-r4-debug-startup.png`, `api28-r4-preserved-state.json`, `api28-r4-ui.json`, `shade-action.xml`, `api28-r4-restart.json`, `api28-r4-actions.log`, `api28-r4-clean.json`, and `api28-r4-clean.png`. Playwright produces its HTML and JSON report; CI retains those as an artifact.

This report records the native **debug** test and production browser regression. The signed APK must additionally pass installation and startup checks before the draft release is published. This is enforced as a publication step, not an automated device gate in GitHub Actions. Physical-device vendor behavior, long-term battery restrictions, Android versions other than 9, and a complete legacy UI parity audit remain outside this regression test.

Rollback is available through the unchanged r3 tag and the small r4 commit. Rolling back source is safe; installing an APK with a lower versionCode on a user's phone may require data migration and must not be done by uninstalling without a backup.
