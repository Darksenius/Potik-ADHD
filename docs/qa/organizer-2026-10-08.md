# Потік: перевірка спрощеного органайзера

Початок робіт: 08.10.2026. Оновлено: 09.10.2026. Кандидат **1.7.6.r1** (`package.json`: `1.7.6-r1`, Android versionCode `1070601`). Основа для відкату коду: `v1.7.5.r4`, `fc8bdc84191945b3e994673cf96ecc32429b8699`. Робоча гілка: `improve/organizer-2026-10-08`.

Статус: реалізований і локально перевірений блок простих/запланованих задач, календаря, налаштувань і збереження. Це не заява про завершення всіх можливостей органайзера або публікацію стабільного релізу. Підтримка старого формату даних не є вимогою за рішенням власника; збереження нових даних обов’язкове.

## Що змінено

- Чотири головні вкладки: Сьогодні, План, Вхідні, Ще. Другорядні розділи залишаються доступними.
- У редакторі два головні типи: Проста і Запланована. Решта 11 доступні через додаткові можливості; призначення й конкретні приклади всіх типів наведені в [дорожній карті](../roadmap/TASK-TYPES.md).
- Один редактор та ID задачі зі списку й календаря. Обраний день календаря заповнюється у формі; задачі показуються перед журналом і налаштуваннями дня.
- Майбутня задача не потрапляє у Сьогодні завчасно. Усі задачі дозволяють знайти майбутні, відкладені, зональні, виконані та «Колись». Папки — компактний список, ручний порядок не перекривається прихованим сортуванням.
- Дата визначає день, час визначає сигнал. Попередній сигнал лише за явно вибраним інтервалом; приховане нагадування напередодні о 12:00 вилучене. Збереження минулого часу вимагає явного вибору, без тихого перенесення на завтра.
- Перенесення узгоджує календар і сигнал. Хвилинна точність не втрачає нагадування через секунди; редагування дати простої задачі скидає застаріле відкладення.
- Налаштування: світла/темна/системна тема, менше анімацій, приховування XP, стан дозволу Android на сповіщення, резервні копії, ліцензія й вихідний код. Мова наразі українська; повна англійська локалізація запланована.
- Валідація копії до зміни стану, окремі режими додавання та повного відновлення, резерв перед імпортом і скасування імпорту. Задачі з однаковою назвою, але різними датами не склеюються. Повна історія фокусу входить у копію.
- Room є основним сховищем Android. Snapshot і підтвердження конкретних команд записуються однією транзакцією. Невдалий запис не видається за успіх через localStorage; непідтверджені команди залишаються в черзі. Файлова копія записується атомарно.
- WebView більше не оголошує Android-сповіщення доставленим до receiver. Підтвердження містить час конкретного спрацювання, тому стара команда не вимикає новий сигнал перенесеної задачі. Receiver перевіряє дозвіл і канал, зберігає дедуплікацію доставки у фоні.
- Прибрані невикористані поля UI та сторонній контракт ForegroundService, мертвий placeholder сторінки віджета, зайві імпорти. README описує поточні React-джерела; звичайна збірка не копіює APK в особисту папку.

## Відтворення та звіти

```text
npm run sync
TEST_PRODUCTION=1 PLAYWRIGHT_CHANNEL=chromium npm test
npx tsc --noUnusedLocals --noUnusedParameters --pretty false
android/gradlew -p android :app:testDebugUnitTest :app:assembleDebug :app:connectedDebugAndroidTest
```

Для Windows змінні встановлюються через `$env:...`, Gradle запускається як `android\gradlew.bat`. Потрібні Node.js 22+, JDK 21, Android SDK 36, встановлений Chromium для Playwright і окремий тестовий пристрій. Збереження скриншотів/логів не вимагає та не використовує особистих даних.

- `playwright-report/index.html` — інтерактивний звіт; `test-results/results.json` — машинний підсумок і скриншоти тестів.
- `android/app/build/reports/androidTests/connected/debug/index.html` — Android-звіт; `android/app/build/outputs/androidTest-results/connected/debug/` — XML/журнали.
- Локальний корінь доказів: `E:\projects\codex-files\Potik\audit-2026-10-07`, журнал `native-final-2026-10-09.log`.
- Тестовий AVD: `D:\Android\Potik-Test\avd\Potik_API28.avd`; SDK та образ API 28 на D. Це не підтверджує справність усіх сторонніх або раніше налаштованих емуляторів.
- GitHub workflow `Migration validation` запускається також для `improve/**` і зберігає звіти як артефакт. Локальний успіх не підміняє фактичний статус GitHub Actions.

## Що ще потрібно

1. Перед стабільним релізом: підписана збірка та її установка/запуск; Android 13/14+ з відмовою/повторним наданням дозволів; робота після перезавантаження, Doze, зміни часового поясу і тривалого закриття процесу; фізичний Android 9 власника.
2. Фонові майбутні повтори ще залежать від оновлення знімка застосунком; поточний календар не проектує всі повтори наперед. Потрібні окремі входження та історія.
3. Додаткові типи зберегли відомі обмеження: Pomodoro на JS-тиках; сім прапорців звички замість історії; неузгоджене завершення зональної задачі між поверхнями; статистика XP/скасування виконання; семантика старого типу alarm без повторення. Вони не оголошені повністю переробленими.
4. Домашній Android-віджет ще не реалізовано. У дорожній карті описані читання спільного Room, швидке додавання, відкриття задачі та наступний етап безпечних команд.
5. Дії «відкласти» у системному сповіщенні ще мають окремий фоновий механізм; їх потрібно остаточно узгодити з редактором, зокрема скасування нагадування після виконання/видалення.
6. Дедуплікація сповіщень і команда підтвердження не є однією транзакцією із системним NotificationManager. Аварія точно між показом, реєстром доставки та командою потребує окремого випробування; не обіцяємо математичного exactly-once між цими системами.

Відкат коду доступний через попередній тег і окрему робочу гілку. Встановлення старішого APK та сумісність його даних не є тим самим, що відкат коду; автоматичного видалення даних для такого відкату немає.
