## Що виправлено

| Сценарій | Зміна |
|---|---|
| Швидке введення у Вхідних при відмові сховища | Текст залишається. Повторна спроба редагує той самий запис у пам'яті, а не створює дубль; після успіху поле очищається. |
| Android відхиляє JSON/Markdown експорт | Явне повідомлення про невдале збереження замість мовчазного повернення. |
| Імпорт нової зони після видалення старої | Збережені прив'язки, перенесення, шаблони й винятки вимкнення захищають ID. Перенесення отримують ту саму карту нових ID, що й задача. Повторний імпорт не дублює їх. |
| Накладені повторні блоки зон | Заголовок, задачі й нативний розклад використовують однаковий порядок пріоритетів. Раніше повторне додавання вже наявної зони міняло порядок лише у `getActiveZones`. |
| Порожній або зворотний часовий проміжок | Редактор пояснює проблему та лишається відкритим. Переходи через опівніч складаються з двох проміжків; 00:00 як кінець дня зберігається як 24:00. Store також відхиляє некоректні нові діапазони. |
| Видалена/очищена задача залишає порожній сигнал | Очищаються її тимчасові нагадування й пріоритети; відновлення з кошика не відроджує старий сигнал. |
| Черга «Виконано», потім «Перенести» | Підготовка холодного запуску не вкладає пізніше перенесення в знімок попереднього завершення. Undo не відновлює дію, яка не застосувалася. |
| Дія при наступному вході в зону | JS матеріалізує виконання лише адресованої задачі на момент натискання; старі дії не повертають уже новіше виконання назад. Нативна кнопка перевіряє те саме поточне виконання, що й добір карток. |
| Подвійний Done інтервальної задачі доставлений пізніше | Час старого натискання не може завершити наступний інтервал. Нативна проєкція виводить наступний момент із часу завершення та `repeatMs`. |
| Повторне натискання старої картки | Дії мають ідентичність задачі/розкладу/перенесення/входу в зону. Старий токен не переносить задачу вдруге; свіжо розгорнута картка має новий токен. |
| Зміна часу або часового поясу при закритому UI | Нативний розклад перебудовується з локальних профілів дня; системні події переплановують сигнали та оновлюють постійне сповіщення. Дні переходу на літній/зимовий час мають фактичні 23/25 годин. |
| Android відкидає підтвердження після швидкої серії карток | У журналі Android підтверджено `Package enqueue rate ... Shedding ... id 42`. Останнє підтвердження має одну відкладену спробу оновлення через 2 секунди. Команда введення не виконується повторно. |

## Межі

Збережені перенесення й snooze лишаються конкретними моментами часу. Зміна часового поясу перебудовує локальні зони й звичайні сигнали, але не змінює вже прийняту тривалість 23 годин або збережені `startAt/endAt` перенесення.

Повна історія окремих виконань ще не реалізована. Денна статистика читає поточні задачі, тому після скиду повтору може втрачати попередній результат, навіть якщо агрегат зберігся у журналі дня. Це окремий наступний крок моделі. Застарілі щоденні дії без певного виконання й надалі зберігаються як нотатка для ручної перевірки.

Фізичний телефон не підключено; перевірки Android виконуються на власному AVD. Це не доводить тривалу роботу під обмеженнями батареї конкретного телефона.
